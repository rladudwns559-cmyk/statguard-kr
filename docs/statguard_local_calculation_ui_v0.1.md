# StatGuard CSV 계산 엔진 연결

이번 단계에서 CSV 조건 확인 화면을 기존 Python 계산 코어에 연결했다. 사용자는 `/statguard`에서 자료·조건을 확인한 뒤 **계산 실행**을 누르면 결과, 실제 계산식, 사용한 원본 행을 확인할 수 있다. 지원 범위는 기존 화면의 합계·평균·증감률 3개로 유지한다. 기존 코어의 다른 연산을 제거하거나 새 계산 알고리즘을 만들지 않았다.

## 실행과 데이터 처리

로컬 주소는 `http://127.0.0.1:5173/statguard`다. 기존 화면이 열려 있다면 새로고침한다. 예제 CSV 선택 → 숫자 열·단위·범위 지정 → 확인란 → 이 조건으로 확인 → 계산 실행 순서다. PC에서 확인 서버를 다시 실행하려면 프로젝트 루트에서 설치된 Node로 `node frontend/scripts/statguard-local.mjs`를 실행한다. 기본 포트는 5173이며 다른 프로그램이 사용 중이면 자동으로 다른 프로그램을 종료하거나 다른 포트를 고르지 않는다.

미리보기는 브라우저 안에서 처리한다. **계산 실행을 눌렀을 때만** 원본 CSV bytes와 확정 조건을 같은 PC의 로컬 실행기로 전달한다. 로컬 실행기는 기존 Python 코어를 격리된 단일 프로세스로 실행한다. 자료는 stdin/stdout과 메모리에만 존재하며 업로드 폴더·DB·결과 파일에 보관하지 않는다. GPT·검색·외부 서버에 보내지 않으며 유료 API 키도 필요하지 않다. 새로고침·페이지 이동·자료 비우기로 작업 상태를 버린다. 메모리의 포렌식 삭제를 보장하는 기능은 아니다.

`frontend/scripts/statguard-calculation-plugin.mjs`는 로컬 실행기에서만 등록한다. 운영 backend·provider·인증·API/DB 구조와 production 배포에는 연결하지 않았다. 일반 정적 웹 배포에 계산 서버가 추가된 것은 아니며, 로컬 실행기 없이 열면 계산 연결 안내 또는 연결 실패를 표시한다.

## 원본과 계산 조건 연결

1. 브라우저가 파일 전체의 SHA-256과 미리보기 `[columns, rows]`의 UTF-8 compact JSON SHA-256을 계산한다. 행·열·문자열 순서와 값은 바꾸지 않는다.
2. 사용자 확인 이후 별도 계산 버튼이 원본 bytes, 실제 해석에 사용한 인코딩, 두 hash, 단위, 명시적 spec, 무작위 request ID를 전달한다.
3. Python 연결 어댑터는 원본 hash를 다시 검사하고 기존 `load_csv_bytes`와 `CalculationSpec.from_mapping`으로 재검증한다. 엔진의 전체 표 해석 hash가 브라우저와 다르면 결과를 만들지 않는다. CP949 해석 차이를 추측으로 보정하지 않는다.
4. 기존 `execute`가 Decimal로 계산하고 데이터 버전·계산 ID·결과·식·사용 행·누락 제외 행을 반환한다. 단위는 여전히 사용자 지정이며 사실성을 인증한 값이 아니다.
5. 브라우저는 응답의 request ID, source·preview hash, spec·단위·엔진 버전, 행 범위·중복·집합 관계를 확인한 뒤 표시한다. 화면에서 별도의 부동소수점 계산으로 엔진 값을 덮어쓰지 않는다.

클라이언트 사전 검사는 편의 기능이며 Python 검증을 대체하지 않는다. 결과를 새로운 사실성·인과관계 판정이나 전체 답변 검증으로 표현하지 않는다. 이번 단계에는 수치 주장 비교나 허용오차 판정을 연결하지 않았다.

## 결과 화면

- 정확한 십진수 결과와 단위. 브라우저 Number로 바꾸지 않고 엔진 문자열을 표시한다.
- 실제 엔진 계산식. 증감률 예제는 `(1178 - 1000) / 1000 * 100`과 결과 `17.8%`다.
- 선택 범위·기준 범위 각각의 선택 수, 실제 사용 수, 빈 값 제외 수, 조건 밖 행 수.
- 사용한 원본 행과 제외된 빈 값 행을 별도로 볼 수 있는 표. 20행씩 페이지를 이동하며, 기본 미리보기의 10행 제한과 독립적이다.
- 원본 행 번호는 열 이름을 제외한 데이터 record 순서다. 따옴표 안의 개행을 별도 데이터 행으로 세지 않는다.
- 접을 수 있는 데이터 버전·계산 ID·원본 hash·정밀도 정보.

## 실패와 상태 변경

자료·인코딩·계산 종류·숫자 열·단위·범위·빈 값 정책·확인 상태가 바뀌면 진행 중 요청을 취소하고 기존 결과를 지운다. 늦게 도착한 이전 응답은 표시하지 않는다. 중복 실행을 막고 실패 뒤 자동 재시도하지 않는다.

엔진 프로세스 8초, 화면 요청 12초의 상한을 둔다. 시간 초과·연결 실패·원본 불일치·미리보기 해석 차이·수치 오류를 제한된 코드와 한국어 안내로 표시한다. 예외 원문·Python stderr·입력 CSV를 로그나 오류 메시지로 전달하지 않는다.

로컬 HTTP 연결은 loopback 접속, 정확한 Host·Origin, JSON과 전용 요청 header를 요구한다. 외부 origin의 preflight를 허용하지 않는다. 요청 body 1,500,000 bytes, 원본 CSV 1 MiB, 동시 작업 2개, 엔진 출력 750,000 bytes로 제한한다. 자식 프로세스는 shell을 사용하지 않고 고정 Python 진입점만 실행하며 provider·DB 비밀 환경변수를 상속하지 않는다. 이 제한은 운영용 인증·네트워크 격리를 대체하는 제품 배포 설계가 아니다.

## 검증 결과

기존 프런트엔드 168개와 신규 계산 화면·응답 연결 23개, 총 **191개 통과**. Python 기존 코어 83개와 신규 연결 어댑터 21개, 총 **104개 통과**. 로컬 실행기의 origin·크기·동시 실행·취소·프로세스 실패 처리 **14개 통과**. 이들은 합계 309개의 서로 다른 자동 테스트이며 새 화면 재검사 23개를 다시 합산하지 않는다.

첫 TypeScript 검사에서 새 테스트 fixture의 누락 필드와 빈 배열 타입 선언 두 건이 발견돼 수정했다. 수정 후 타입 검사와 해당 화면 테스트 23개 재검사가 통과했다. 프런트엔드 전체 테스트 본문은 최초 191/191 통과했으며 skip 0이다. 로컬 build가 성공했고 배포하지 않았다. build 출력 폴더를 프로젝트 밖의 새 검증 경로로 지정해 기존 출력 폴더를 비우지 않는다는 안내 warning이 있었다.

외부 통신을 차단한 새 Edge 프로필에서 **실제 Python 코어**를 호출하는 합성 CSV 6개 흐름과 36개 확인 항목을 통과했다. 합계 4938명, 평균 823명, 증감률 17.8%, 빈 값 명시적 제외 30명, CP949 1건, 41행 페이지 보기의 결과와 행 번호를 확인했다. 값은 UI 테스트 mock 결과를 재사용한 것이 아니다. 원본·미리보기 hash 불일치와 외부 Origin 요청도 실제 로컬 endpoint에서 거부했다.

브라우저 흐름의 정상 로컬 계산 요청은 6회였으며, 별도 거부 검사 3회와 capabilities 확인 1회가 있었다. 외부 검색/fetch·유료 API·배포·과거 live 세트 재실행은 모두 0이다. 새 모바일 검사는 데스크톱 Edge의 390px·320px 너비 점검이며 실제 휴대전화 조작은 미검증이다. 전체 과거 backend/evaluator suite를 실행한 것으로 해석하지 않는다.

## 일정과 다음 한 단계

4주 마감 계획에서 CSV 입력·조건 확인에 이어 **기존 계산 엔진 결과와 사용 행 표시**를 완료했다. 프로젝트 전체 완료율을 이 milestone 완료율과 같게 표시하지 않는다. 다음 범위는 **계산 결과에 사람이 직접 입력한 수치 주장 하나를 연결해 비교하는 기능** 정도로 제한하고, 현재 승인 없이 자동 구현하지 않는다. 새 모델·고급 통계검정·파일 장기 보관·GPT 자동 분석·배포는 추가하지 않았다.
