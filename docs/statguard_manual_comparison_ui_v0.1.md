# StatGuard 직접 입력 수치 비교

CSV에서 계산한 결과에 사람이 직접 입력한 수치 하나를 연결해 일치 여부와 차이를 표시한다. 기존 합계·평균·증감률, 계산식, 사용한 행과 빈 값 제외 행 보기는 유지한다. 유료 API·GPT·외부 검색·배포는 사용하지 않는다.

## 사용 순서

`http://127.0.0.1:5173/statguard`를 새로고침한다. CSV 선택 → 계산 조건 확인 → 계산 실행 후 결과 카드의 **내 수치와 비교하기**에 숫자를 입력하고 **수치 비교**를 누른다. 숫자의 단위는 현재 계산 결과의 단위로 고정한다. 숫자 뒤에 단위나 `%`를 붙이지 않는다.

기본 허용 차이는 0이다. 정확히 같은 값만 일치로 표시한다. 반올림을 고려할 필요가 있을 때만 ‘허용 차이 설정’을 열어 절대 차이를 직접 지정한다. 지정 범위의 경계값도 포함하며, 임의의 허용 차이를 자동 선택하거나 조정하지 않는다.

| 계산 결과 | 직접 입력 | 허용 차이 | 표시 |
| --- | --- | --- | --- |
| 17.8% | 17.8 | 0 | 정확히 일치, 차이 0퍼센트포인트 |
| 17.8% | 23 | 0 | 불일치, 입력값이 5.2퍼센트포인트 높음 |
| 17.8% | 15 | 0 | 불일치, 입력값이 2.8퍼센트포인트 낮음 |
| 17.8% | 17.9 | 0.1 | 허용 차이 이내, 정확히 같은 값은 아님 |
| 4938명 | 5000 | 0 | 불일치, 입력값이 62명 높음 |

퍼센트 값끼리의 절대 차이는 **퍼센트포인트**로 표시한다. 상대적인 증가율·오차율과 혼동하지 않도록 상대 비율은 이번 범위에 추가하지 않았다. 따라서 계산 결과가 0인 경우에도 나눗셈 없이 차이를 표시할 수 있다.

## 계산과 연결 경계

기존 `verify_numeric_claim`과 `NumericClaim`, `Tolerance`를 재사용한다. 비교를 실행할 때 현재 계산의 원본 bytes와 확인된 spec을 같은 PC의 기존 연결 경로로 다시 전달한다. 서버 메모리에 과거 계산값을 보관하거나 클라이언트가 보낸 계산 결과를 신뢰하지 않는다.

연결 어댑터는 원본·미리보기 hash를 다시 검사하고 기존 엔진으로 재계산한다. 데이터 버전·계산 ID·단위가 현재 화면의 대상과 맞는 경우에만 비교한다. 입력값에서 계산값을 뺀 signed 차이와 그 절댓값을 기존 엔진과 동일한 Decimal 정밀도 34자리·ROUND_HALF_EVEN 문맥으로 산출한다. 프런트엔드 Number로 일치 여부나 차이를 다시 계산하지 않는다.

`EXACT_MATCH`는 차이 0, `WITHIN_TOLERANCE`는 0이 아닌 차이가 명시적 허용 범위 안, `MISMATCH`는 범위 밖이다. 이는 기존 verifier의 제한된 수치 비교 결과를 화면용으로 구분한 상태다. 문장의 의미·표의 사실성·인과관계·전체 답변이 참이라는 판정이 아니다.

입력은 기존 core와 동일하게 정수부 최대 18자리·소수부 최대 6자리의 일반 십진수 표기를 지원한다. 올바른 천 단위 쉼표와 음수는 허용하며 수식·지수 표기·NaN·무한대·단위 접미사는 거부한다. 허용 차이는 0 이상 10^18 이하이며 상대 허용오차는 0으로 고정한다. 소수점이 순환하는 평균 등에는 사용자가 의도한 절대 허용 차이를 직접 명시해야 한다.

## 상태 변경과 데이터 처리

- 입력값·허용 차이를 변경하면 이전 비교 결과와 오류를 지우고 진행 중 비교를 취소한다. 늦게 도착한 이전 입력의 응답을 표시하지 않는다.
- CSV·계산 조건 변경으로 기존 계산이 해제되면 비교 입력·판정도 사라진다. 새 계산에 이전 판정을 붙이지 않는다.
- 입력 단위는 현재 계산에 고정한다. 연결이나 단위가 맞지 않으면 일치/불일치를 만들지 않고 비교 오류를 표시한다.
- 시간 초과·연결 실패 뒤 자동 재시도하지 않는다. 기존 로컬 실행기의 요청 크기·동시 실행·origin·프로세스 제한을 유지한다.
- 비교 입력과 결과는 브라우저·로컬 프로세스 메모리에서만 다룬다. 파일·DB·localStorage·sessionStorage에 저장하거나 GPT로 전송하지 않는다. 원본 CSV와 동일하게 새로고침 시 작업 상태를 버린다.

## 검증

최종 자동 테스트는 프런트엔드 220개, Python 기존 계산·연결·수치 비교 125개, Node 로컬 연결 14개로 **서로 다른 359개 모두 통과, skip 0**이다. 신규 검사는 화면·응답 연결 29개와 Python 비교 21개다. 기존 계산 core 소스는 변경하지 않았다. TypeScript 검사와 로컬 build가 성공했으며 배포하지 않았다.

첫 전체 프런트엔드 실행에서는 220개 테스트 본문이 통과했지만 별도 Node 전용 테스트 파일이 jsdom 실행기에 함께 수집돼 1개 suite의 import가 실패했다. 이 실행은 전체 통과로 기록하지 않았다. `frontend/vite.config.ts`와 격리된 검증 설정에서 화면 테스트 대상을 `src/**/*.test.{ts,tsx}`로 명시했다. Node 전용 14개는 기존 Node 실행기로 별도 실행했고, 최종 전체 화면 220개와 Node 14개가 모두 통과했다. 테스트를 삭제하거나 skip 처리한 변경은 없다.

외부 통신을 차단한 새 Edge 프로필에서 실제 Python core에 연결해 8개 수치 비교와 45개 확인 항목을 통과했다. 정확 일치, 양·음 방향 차이, 허용 차이 경계, 범위 초과, 명 단위, 평균, 0인 결과를 확인했다. 기존 결과·사용 행 표시, 부모 계산 변경 시 비교 초기화, 잘못된 연결·단위 거부, 입력 변경 시 판정 제거, 모바일 390px·320px 너비도 점검했다. 프런트엔드 단위 테스트의 mock 응답을 실제 엔진 검증 결과로 계산하지 않았다.

브라우저 검증의 정상 로컬 계산 4회·비교 8회와 별도 거부 요청 2회가 있었다. 외부 요청·유료 호출·배포·과거 live 평가 재실행은 모두 0이다. 실제 휴대전화의 키보드·터치와 전체 과거 backend/evaluator suite는 미검증이다.

기존 1021개 기준 파일 중 1016개는 SHA-256이 같고, 승인 범위의 화면·전용 CSS·연결 어댑터·테스트 실행 설정 5개만 변경했다. 과거 보고서·평가 판정·fixture와 원래 계산 core는 보존했다. 상세 기록은 `artifacts/statguard_manual_comparison_ui_v0.1/`에 있다.

## 4주 마감 범위

CSV 입력 → 조건 확인 → 계산 → 사용한 행 → 직접 입력한 수치 비교까지 핵심 흐름을 연결했다. 다음에는 새 분석 기능보다 소수 실제 CSV 사용 점검과 오류·문구 정리에 집중할 수 있다. 이번 승인으로 다음 기능, 유료 호출, 배포를 자동 진행하지 않는다.
