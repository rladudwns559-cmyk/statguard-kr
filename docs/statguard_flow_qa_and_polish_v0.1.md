# StatGuard CSV 전체 흐름 점검 및 화면 정리 v0.1

완료 범위: 작은 합성 CSV로 업로드 → 조건 확인 → 기존 엔진 계산 → 계산식·사용 행 확인 → 직접 입력 수치 비교를 점검했다. 기존 계산 엔진과 연결 방식은 유지했다. 기능 확장·유료 API·배포는 하지 않았다.

## 점검 자료와 결과

자료는 `data/statguard_flow_qa_v0.1/`의 합성 CSV 8종과 숫자 오류 수정본 1개다. 실제 통계 자료나 연구 성능 평가셋이 아니다. 기대값·인코딩·입력 해시는 해당 폴더의 manifest에 보존했다.

| 사례 | 기대 및 실제 관측 | 결과 |
|---|---|---|
| Q01 방문자 증감 | A 지역 2023→2024: 17.8%. 직접 입력 23%와 5.2%p 차이. 선택 행 2, 기준 행 1 | 일치 |
| Q02 천 단위 쉼표·소수 매출 | 합계 2,500원, 입력 2,500원과 정확히 일치. 사용 행 1~3 | 일치 |
| Q03 한글 CP949 | 합계 30명, 입력 31명과 1명 차이. 평균으로 변경 후 15명과 일치. 변경 시 이전 비교 결과 초기화 | 일치 |
| Q04 미리보기 밖 12번째 빈 값 | 기본 정책은 중단하고 12행 안내. 사용자가 제외 선택 후 66원, 사용 1~11행·제외 12행 확인 | 일치 |
| Q05 기준값 0 | 증감률 계산 차단. 합계로 조건 변경 후 10원, 입력 11원과 1원 차이 | 일치 |
| Q06 숫자 오류·수정본 | 11행의 숫자 형식 오류 안내 및 계산 차단. 같은 표시 파일명으로 수정본 업로드 후 66원과 일치 | 일치 |

잘못된 입력의 차단은 정상 기대 동작이다. 모든 CSV가 그대로 계산 가능했다고 해석하지 않는다. 최종 브라우저 실행은 계산·수치 비교 각 8회다(평균 재계산 포함). 최초 점검·재검사를 포함한 전체 로컬 호출 수와 혼동하지 않는다.

## 확인 후 수정한 네 부분

| 항목 | 수정 전 실제 관측 | 수정 후 |
|---|---|---|
| 현재 자료 표시 | 예제 선택 뒤 파일 선택기에 이전 이름이 남음 | 현재 자료 이름을 별도 표시, 선택기 초기화. 같은 이름 수정본 재업로드 가능 |
| 오류 위치 | 미리보기 10행 밖의 숫자 오류 위치를 찾기 어려움 | 잘못된 숫자·빈 값의 원본 데이터 행 번호 안내. 긴 목록은 첫 5개와 나머지 개수 표시 |
| 계산 후 조건 반복 | 결과 아래 전체 조건 검토가 반복되어 길어짐 | 완료 후 ‘사용한 계산 조건 다시 보기’로 접고 필요 시 열람. 조건 수정 시 다시 확인하도록 복구 |
| 좁은 화면 | 320px 화면에서 긴 단위 때문에 문서 폭 350px | 긴 이름·단위 줄바꿈과 입력 배치 정리. 320/390px 넘침 검사 통과 |

숫자 처리·빈 값 정책·계산식·수치 비교 판정 기준을 완화하지 않았다. 긴 숫자는 자르거나 반올림해 숨기지 않았다. 극단적으로 긴 단위는 여러 줄이 되어 읽기 불편할 수 있다.

## 검증 기록

- 전체 화면 회귀검사: 15파일, 226개 통과(새 회귀검사 6개 포함), 실패·skip 0.
- 새 회귀검사 최종 재검사: 6개 통과. 위 226개에 중복 합산하지 않음.
- 계산 엔진·로컬 연결 Python 검사: 125개 통과.
- 로컬 전달 경계 Node 검사: 14개 통과, 실패·skip 0.
- 중복 제외 자동 검사 합계: 365개 통과.
- 실제 Edge와 실제 로컬 계산 엔진의 최종 브라우저 검사: 79개 통과. 최초 브라우저 검사 73개 통과 기록도 별도 보존.
- 최종 TypeScript 검사·화면 빌드 통과. 최초 TypeScript 검사에서 새 테스트의 지원하지 않는 옵션 2건이 발견되어 테스트만 수정 후 통과했다. 계산 오류는 아니었다.
- 빌드 경고 1종: 빌드 출력 위치가 프로젝트 밖이라 자동 비우지 않는다는 안내. 별도 점검 폴더 사용에 따른 것으로 배포하지 않았다.
- 외부 요청 시도 0, 화면 JavaScript 오류 0. 브라우저는 loopback만 허용하고 외부 요청을 차단하도록 설정했다.

320/390px는 데스크톱 Edge의 좁은 화면 검사다. 실제 휴대전화·실제 브라우저 200% 확대는 이번에 검증하지 않았다. 전체 과거 evaluator/backend 테스트는 이번 범위가 아니며 통과로 세지 않았다.

## 파일 경계와 무결성

기존 1,040파일을 작업 전후 대조했다. 1,037파일은 SHA-256 동일하며 허용된 화면 파일 3개만 변경됐다: StatGuardWorkspace.tsx, conditions.ts, statguard.css. 기존 계산 엔진·로컬 연결·설정·이전 보고서·연구 artifact는 변경하지 않았다.

신규 파일: 화면 회귀검사 1개, 합성 CSV 9개와 manifest, 이 보고서, 독립 점검 결과·로그·diff·화면 이미지·무결성 manifest. 원본 CSV나 사용자 자료를 찾아 읽거나 수정하지 않았다. 이번 fixtures는 점검용 신규 자료다.

결과 기록은 `artifacts/statguard_flow_qa_and_polish_v0.1/`에 있다. `frontend_initial.json`은 전체 226검사, `frontend_final.json`은 추가 6검사 재실행이며 서로 다른 모집단으로 합산하지 않는다. `browser_initial.json`과 `browser_results.json`도 별도 실행 기록이다.

유료 API 호출 0 / 외부 검색·fetch 0 / production 변경 0 / 과거 live 세트 재실행 0. 기존 v0.7 RED 및 03 원인 미확정 판정은 변경하지 않는다.

## 마무리 범위

이번 요청의 점검·화면 정리는 완료했다. 연구 정확도·실제 사용자 사용성 전체 검증을 완료했다고 주장하지 않는다. 4주 범위를 유지하려면 다음 확인은 사용자가 가진 작은 CSV 한 개로 직접 사용해 보는 정도로 제한하고, 새 기능 확장은 별도로 결정한다.
