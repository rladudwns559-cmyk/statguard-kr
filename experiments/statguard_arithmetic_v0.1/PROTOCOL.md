# 답변 속 계산 검산 평가 프로토콜 v0.1 (실행 전 고정)

작성: 2026-11-24. 모듈 `src/when2warn/statguard/arithmetic.py`(statguard-arithmetic-v0.1)를 평가한다. API 호출 없음(저장된 답변만).

## 1. 질문

CSV 없이 답변 안에 적힌 계산식만 다시 계산해서(LLM 없음) 오답을 얼마나, 얼마나 정확하게 잡는가? CSV 재계산(StatGuard)이 잡지 못한 오답을 추가로 잡는가?

## 2. 데이터

- **G1 (모듈을 만들기 전 패턴을 훑어본 답변):** `statguard_comparison_v0.1`의 답 360개(gpt-6-luna·gpt-4o-mini·gpt-5-mini 원래 답변).
- **G2 (처음 적용하는 답변):** gpt-6-luna 반복·조건 답변 528개(A_r2·A_r3·B·C·C_r2·C_r3, 본 세트), 교정 실험에서 고쳐 쓴 답변 전부(gpt-6-luna: `statguard_correction_v0.1`, gpt-4o-mini·gpt-5-mini: `statguard_comparison_v0.1`의 R·S 1·2회차 응답).

## 3. 판정

- 계산식 하나: 답변에 적힌 결과가 재계산 값과 결과의 마지막 자릿수 반 단위를 넘어 다르면 INCONSISTENT.
- 답변 하나: INCONSISTENT 계산식이 하나라도 있으면 ‘검산 불일치’.
- 정답 여부는 각 벤치마크 `evaluate.py`로 채점(최종값 기준).

## 4. 지표 (G1·G2 따로, 그리고 합계)

1. 계산식을 쓴 답변 수, 검산 불일치 답변 수.
2. **정밀도:** 검산 불일치 답변 중 실제 오답 비율. 정답인데 불일치로 잡힌 답변은 사례를 그대로 보고한다(중간 계산만 틀리고 최종값은 맞는 경우 가능).
3. **재현율:** 전체 오답 중 검산 불일치로 잡힌 비율.
4. **추가 가치:** 검산이 잡은 오답 중 CSV 재계산(규칙 v0.7 고정 사본)의 FLAG가 아니었던 수.

## 5. 해석 한계

- 계산식을 적지 않는 모델(예: gpt-6-luna 원래 답변)에서는 거의 작동하지 않는다.
- 데이터를 잘못 옮겨 적고 그 숫자로 정확히 계산한 경우는 원리상 잡지 못한다.

## 변경 기록

- 2026-11-24, 첫 실행 후 (v0.1 → v0.1.1, 버그 수정): 첫 실행 결과는 검산 불일치 107개 중 실제 오답 100개(93.5%)였다(`results/REPORT_v0.1_before_fix.md`). ‘정답인데 불일치’ 사례를 확인하니 두 건이 **긴 식의 일부만 잘라 읽은 버그**였다 — ① 등호가 이어지는 문장에서 앞 식을 읽다 실패한 뒤 뒤 식의 꼬리(“51,764,822 × 100”)만 읽음, ② “방문자수(500) × 100”처럼 낱말이 섞인 식의 꼬리만 읽음. 등호마다 바로 앞의 식 전체만 읽고, 낱말에 붙은 식은 건너뛰도록 고쳤다(회귀 테스트 추가). **이 수정은 결과를 본 뒤에 한 것**이며, 수정 후 같은 데이터로 다시 실행한 결과를 `results/REPORT.md`에 둔다.
- 반올림 대신 버림(예: 7.6666…→“7.666”)으로 잡힌 경우는 3장의 판정 규칙(반올림 기준) 그대로 두고 ‘정답인데 불일치’로 보고한다.
