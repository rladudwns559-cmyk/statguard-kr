# StatGuard-KR 비교 실험 프로토콜 v0.1 (실행 전 고정)

작성: 2026-11-24. 이 문서는 새 LLM 호출을 하기 전에 작성했으며, 결과를 본 뒤 조건·문구·지표를 바꾸지 않는다. 바꿔야 하면 아래 ‘변경 기록’에 이유와 함께 남긴다.

## 1. 질문

- **Q1 (검증 방식 비교):** AI가 쓴 데이터 분석 답변을 검증할 때, LLM에게 판단을 맡기는 방식(LLM 심판, 자기 일관성)과 StatGuard(규칙 기반 재계산)는 **틀린 답을 통과시키는 비율**이 얼마나 다른가?
- **Q2 (모델 일반화):** 답변 모델을 바꿔도 StatGuard의 “통과한 답 중 오답 0건”과 근거 교정 효과(S > R)가 유지되는가?

## 2. 문항·채점

- 기존 벤치마크 v0.1(본 36 + 별도 18), v0.2(본 30 + 별도 14), v0.3(본 22) — 총 120문항, CSV·질문 그대로.
- 정답 여부는 각 벤치마크의 `evaluate.py`(`final_value`, `is_correct`)와 `expected*.json`으로만 판단한다. 기대값은 어떤 모델에게도 주지 않는다.

## 3. 답변 모델 (Q2)

| 모델 | 비고 |
|---|---|
| gpt-6-luna | 기존 조건 A 답변(이미 저장됨, 새로 생성하지 않음) |
| gpt-4o-mini | 새로 생성 |
| gpt-4.1-mini | 새로 생성 |
| gpt-5-mini | 새로 생성 (추론 모델) |

- 지시문·입력은 기존 조건 A와 같다: 지시문 “당신은 표 데이터 분석 도우미입니다. …(최종값 형식 규칙)”, 입력 “파일: … CSV: … 질문: …”, store=false, 재시도 없음, 문항당 1회.
- `max_output_tokens`: 비추론 모델 2500(기존과 같음). gpt-5-mini는 추론 토큰이 출력 한도를 함께 쓰므로 8000, `reasoning.effort`=low. (추론 모델에 2500을 쓰면 답을 끝내지 못하는 형식 오류가 구조적으로 늘어 비교가 불공정해지기 때문.)

## 4. 검증 방식 (Q1)

모든 답변(4모델 × 120 = 480개)에 같은 검증 방식을 적용해 PASS(맞다고 통과) / FLAG(틀렸다고 지적) / HOLD(판단 보류)로 바꾼다.

| 방식 | 내용 |
|---|---|
| StatGuard | 웹과 같은 규칙 추출기 v0.7(`../statguard_correction_v0.1/frozen/claims_v0_7.py`, SHA-256 고정). 불일치 있으면 FLAG, 불일치 없이 일치 있으면 PASS, 그 외 HOLD. LLM 호출 없음. |
| LLM 심판 (gpt-6-luna) | CSV·질문·답변을 주고 “CSV를 직접 확인해 답변의 최종값(판단불가라고 답한 경우 그 판단 포함)이 맞는지” 판정하게 한다. JSON 스키마 `{verdict: 맞음/틀림/판단불가, reason}`. 맞음→PASS, 틀림→FLAG, 판단불가→HOLD. max_output_tokens 2500. |
| LLM 심판 (gpt-5-mini) | 위와 같은 지시, 추론 모델(effort low, max_output_tokens 8000). “더 강한 심판이면 되지 않나”에 대한 비교. |
| 자기 일관성 (gpt-6-luna만) | 기존 조건 A 반복 실행 3회(answers_A, _r2, _r3; 본 세트 88문항만 존재)의 최종값이 셋 다 같으면 PASS(1회차 답을 채택), 다르면 HOLD. 새 호출 없음. |

심판 지시문(고정):
> 당신은 표 데이터 분석 답변을 검토하는 검증자입니다. CSV 자료, 질문, 다른 AI의 답변이 주어집니다. CSV를 직접 확인해 답변의 최종값이 맞는지 판정하세요. 답변이 ‘판단불가’라고 했다면 그 판단이 맞는지 판정하세요. 최종값이 맞으면 ‘맞음’, 틀리면 ‘틀림’, 자료로 확인할 수 없으면 ‘판단불가’를 고르고, 이유를 한두 문장으로 적으세요.

## 5. 교정 (Q2, 새 답변 모델 3종)

`../statguard_correction_v0.1/PROTOCOL.md`의 R(단순 재확인)·S(StatGuard 근거) 조건과 대상 선정 규칙·문구·라운드(최대 2)를 그대로 쓴다. 교정 요청은 **답변을 쓴 그 모델**에게 보낸다(위 3장의 토큰 설정 동일).

## 6. 지표

- Q1, 방식별: 통과(PASS) 수, **통과한 답 중 오답 수(주 지표)**와 그 비율(Clopper–Pearson 95% 상한 병기), 오답 중 지적(FLAG) 수, 정답을 틀렸다고 한 수(오경보), 보류 수. 모델별·전체.
- Q2, 모델별: 원래 정답률, StatGuard 판정 분포, 통과 중 오답, 교정 후(R1·S1·R2·S2) 정답률, 고침·망침.
- 비용: 호출 수·토큰(모델별). 실제 청구액은 OpenAI 화면 기준.

## 7. 예산과 중단 기준

- 호출 상한 2500회. 먼저 모델별 3문항으로 시험 실행해 형식을 확인한 뒤 전체를 실행한다.
- 응답은 `results/cache/`에 저장해 같은 요청은 다시 호출하지 않는다. 키는 기록하지 않는다.
- 응답 자체를 받지 못한 전송 오류(HTTP 429·5xx·시간 초과)만 같은 요청을 최대 3회 다시 보낸다. 받은 응답을 버리고 다시 뽑는 일은 하지 않는다.

## 8. 해석 한계(사전 명시)

- 120문항, 답변 모델 4종(모두 OpenAI), 문항당 1회 실행이다. 통계적 유의성은 주장하지 않고 건수와 신뢰구간 상한만 보고한다.
- LLM 심판은 도구(코드 실행) 없이 판단한다. 코드 실행 도구를 준 LLM은 기존 조건 C(계산 도구)로 따로 보고했다.
- StatGuard의 강점은 “확인할 수 있는 것만 통과”에 있으므로 보류가 많다. 보류율(커버리지)을 반드시 함께 보고한다.

## 변경 기록

- 2026-11-24, 시험 실행(3문항) 후·본 실행 전: LLM 심판 gpt-6-luna의 `max_output_tokens`를 2500 → 8000으로 바꿨다. 시험 실행에서 gpt-6-luna도 추론 토큰을 쓰며, 심판 호출 1건이 추론만으로 2500을 다 써 판정 없이 끝났기 때문이다(심판에게 불리한 조건을 없애기 위함). 답변 모델로서의 gpt-6-luna 설정(기존 조건 A, 2500)은 바꾸지 않았다. 판정 결과를 보고 바꾼 것이 아니라 응답 미완료(status=incomplete)를 보고 바꿨다.
- 2026-11-24, 본 실행 도중(223회 호출 시점, 결과 집계 전) 예산 때문에 중단 후 범위 축소: API 잔액이 $3.23이고 공개 시연 기능이 같은 키를 쓰므로, 이 실험 전체(이미 쓴 호출 포함)의 추정 비용 상한을 **$2.00**으로 걸고 그에 닿으면 자동 중단한다. 이에 맞춰 (1) 답변 모델에서 단가가 가장 높은 gpt-4.1-mini를 뺀다(시험 실행 3건은 저장돼 있으나 집계하지 않음). (2) 실행 순서를 답변 → LLM 심판 gpt-6-luna → 교정(R·S) → LLM 심판 gpt-5-mini로 정해, 예산이 모자라면 뒤 단계부터 빠지게 한다. 빠진 단계는 결과에 ‘미실행’으로 적는다. 추정 비용은 공개 단가(입력/출력 $/1M: gpt-4o-mini 0.15/0.60, gpt-5-mini 0.25/2.00, gpt-6-luna 0.10/0.50 — 기존 실험의 사전 고정 단가)로 계산한다. 중간 결과는 집계하거나 보지 않은 상태에서 정한 변경이다.
