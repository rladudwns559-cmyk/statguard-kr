# StatGuard-KR 벤치마크 실험 프로토콜 v0.1 (실행 전 고정)

작성: 2026-11-20. 이 문서는 LLM 호출 전에 작성했으며, 결과를 본 뒤 조건·지표·허용 차이를 바꾸지 않는다. 바꿔야 하면 v0.2로 새로 기록하고 이유를 남긴다.

## 1. 연구 질문 대응

| RQ | 이 실험에서 보는 것 |
|---|---|
| RQ1 일반 LLM의 오류 유형 | Baseline A·B·C 답변의 정답률과 오류 유형(계산·기준 시점·범위·근거 없는 단정) |
| RQ2 Python 실행 검증의 오류 감소 | StatGuard가 A 답변의 수치 오류를 찾는 정밀도·재현율·F1, 통과시킨 답변의 오류율 |
| RQ3 보류에 의한 잘못된 단정 감소 | 답변 불가 질문에서 StatGuard가 ‘계산 일치’를 잘못 주는 비율, 보류 비율(coverage) |
| RQ4 도메인 간 유지 | 기상·환경·인구·고용·합성 5개 자료별 지표(표본이 작아 경향만 보고) |

## 2. 자료와 문제 세트

- 자료 5종: `datasets.json` (실측 4종 + 합성 1종). 실측 자료는 숫자를 바꾸지 않았다.
- 질문 36개: `questions.json`. 답변 가능 27개(그중 StatGuard 미지원 연산 2개: 기간 범위 합계, %p 차이), 답변 불가 9개(자료 밖 기간·대상 5개, 원인·유의성 해석 4개).
- 기대값: `build_expected.py`가 StatGuard 엔진을 쓰지 않고 분수(Fraction)로 독립 계산 → `expected.json`. 모델 답변을 기대값으로 쓰지 않는다.

## 3. 비교 조건

모델은 `gpt-6-luna` 하나로 고정(OpenAI Responses API, store=false, 질문당 1회, 재시도 없음). 출력 형식은 모든 조건 동일: 한국어 2~4문장 + 마지막 줄 `최종값: <숫자> <단위>` 또는 `최종값: 판단불가`.

| 조건 | 입력 |
|---|---|
| A 일반 LLM | 질문 + CSV 원문 |
| B LLM + 컨텍스트 | A + 자료 설명·열 단위 |
| C LLM + Python 계산 도구 | B + `calculate` 함수 도구(StatGuard 계산 엔진 실행, 최대 4회 호출) |
| 제안: StatGuard (규칙 추출) | A·B·C 답변을 규칙 기반 추출기 v0.1로 주장 추출 → 재계산 → 4상태 판정 |
| 제안: StatGuard (LLM 추출) | A 답변을 `gpt-6-luna` 구조화 출력으로 주장 추출 → 같은 재계산·판정 |

## 4. 판정 규칙

- **답변 정답 여부**: `최종값` 수치가 기대값과 답변 자릿수 기준 반올림 범위(±0.5×10^-자릿수) 안이면 정답. 단위가 다르면 오답. 답변 불가 질문은 `판단불가`일 때만 정답. 형식 위반은 오답.
- **StatGuard 답변 단위 결정**: 주장 중 하나라도 ‘계산 불일치’ → 오류 표시(FLAG). 불일치 없이 ‘계산 일치’가 하나 이상 → 통과(PASS). 그 외 → 보류(HOLD).
- 허용 차이는 엔진과 같은 반올림 규칙이며 실험 중 바꾸지 않는다.

## 5. 지표

1. 조건별 정답률(답변 가능 / 답변 불가 구분).
2. StatGuard 오류 탐지: 결정한 답변(FLAG·PASS) 중 오답 탐지의 Precision·Recall·F1, coverage = 결정 비율, 통과 답변의 오류율 vs 원래 오류율.
3. 잘못된 확인 비율: 답변 불가 질문에서 PASS가 나온 비율(낮을수록 좋음).
4. 오류 주입 세트: 답변 가능·지원 질문마다 정답 문장 1개와 오류 문장(수치 10% 왜곡, 증감률은 기준·비교 시점 뒤바꿈 추가)을 만들어, 규칙/LLM 추출기별 문장 단위 탐지 Precision·Recall·F1과 coverage를 계산.
5. 비용: 입력·출력 토큰과 사전 고정 단가(입력 $0.10/1M, 출력 $0.50/1M, 이전 기록 기준) 추정. 실제 청구액은 OpenAI 화면에서 확인.

## 6. 예산과 중단 기준

- 전체 API 호출 상한 400회. 먼저 3문항으로 시험 실행 후 비용을 확인하고 전체를 실행한다.
- 응답은 `results/cache/`에 저장해 같은 입력을 다시 호출하지 않는다. 키·개인정보는 기록하지 않는다.

## 6-1. 시험 실행 후 조정 (2026-11-20, 전체 실행 전)

시험 실행: A 조건 3문항(S01·P01·S08), C 조건 1문항(V01), LLM 추출 3건. 호출 8회, 추정 $0.0012.

1. LLM 추출기가 ‘모든 월’을 같은 열의 필터 여러 개로 나열하는 경우를 ‘열 식별 실패’로 잘못 보류했다. 같은 열의 값이 그 열의 모든 값이면 전체 행, 일부 여러 값이면 `RANGE_FILTER_UNSUPPORTED` 보류로 바꿨다. 판정 규칙·허용 차이는 바꾸지 않았다.
2. 지표 3을 명확히 했다: 답변 불가 질문에서 모델이 `판단불가`라고 하지 않고 단정한 답변(오답)을 StatGuard가 PASS로 통과시킨 비율. S08처럼 모델이 `판단불가`라고 답하면서 언급한 월별 값이 맞으면 PASS는 정상이다.

## 6-2. 본 실행 후 추출기 수정과 별도 검증 세트 (2026-11-20)

본 실행(36문항 × A·B·C, A의 LLM 추출, 오류 주입 58문장) 결과를 본 뒤 규칙 추출기를 두 번 고쳤다. 고친 버전은 기존 결과를 덮지 않고 나란히 보고한다.

- **v0.2**: 기간 범위(“2014~2023년”, “1~6월”, “상반기”)를 마지막 연·월 하나로 읽던 오류 수정. 문제 세트 작성 후, 본 실행 결과 확인 전에 예시 답변 점검에서 발견.
- **v0.3**: 본 실행 결과의 오탐 분석에서 발견한 4가지 수정 — 수식 안의 단위 없는 숫자 무시, “5,146만 8,217명” 결합, % 단위 열의 시점별 값과 증감률 구분, 분모 범위가 문장에 없는 비율은 보류.

v0.3은 본 세트를 보고 고친 것이므로 본 세트 성능은 낙관적일 수 있다. 이를 확인하기 위해 **별도 검증 세트**(`questions_holdout.json`, 18문항: 답변 가능 16 · 불가 2, 미지원 연산 2 포함)를 v0.3 수정 후 작성하고, A 조건 답변과 LLM 추출만 1회 실행해 v0.3·LLM 추출기를 평가한다. 별도 검증 세트를 본 뒤에는 추출기를 더 고치지 않는다.

## 7. 해석 한계(사전 명시)

- 질문 36개·자료 5종의 소규모 실험이며 통계적 유의성을 주장하지 않는다.
- 규칙 추출기는 이 문제 세트 이전에 합성 예제로 개발했다. 문제 세트를 본 뒤 추출기를 고치면 v0.2로 분리 보고한다.
- 계산 일치는 연결된 계산만 확인하며 답변 전체의 사실·인과관계를 보증하지 않는다.
