# 기간 범위 계산 (추출기 v0.7.1) 평가 프로토콜 (실행 전 고정)

작성: 2026-11-24. API 호출 없음(저장된 답변만).

## 1. 바꾸는 것 (v0.7 → v0.7.1)

v0.7은 “7~12월”, “상반기·하반기”, “1분기”, “2016~2020년”처럼 **자료의 일부 기간을 고르는 범위**를 판정하지 않고 보류한다(RANGE_FILTER_UNSUPPORTED). v0.7.1은 v0.7에 다음만 더한다. 미적용으로 결론 난 v0.8의 절 나누기는 넣지 않는다.

1. **계산 엔진:** 계산 조건에 ‘값 묶음’(`value_sets`: 열 → 허용 값 목록, 그 값 중 하나인 행만 선택)을 추가한다. 값 묶음이 없는 계산은 계산 식별값을 포함해 기존과 완전히 같다.
2. **추출기:** 문장의 범위를 자료의 실제 값으로 바꿀 수 있으면(연도 열, 월 열, ‘YYYY-MM’ 열) 값 묶음으로 계산한다. 대상은 합계·평균·표준편차·분산·중앙값·최댓값·최솟값. 증감률·비율·상관·t-검정에 범위가 있으면 지금처럼 보류한다. 범위를 자료 값으로 바꿀 수 없으면 지금처럼 보류한다.

## 2. 데이터

저장된 답변 전부 1,492개(`statguard_arithmetic_v0.1/run_eval.py`의 `answers()`와 같음).

## 3. 지표 (v0.7과 v0.7.1을 같은 답변에 적용)

- 답변 단위(사전 등록 규칙과 최종값 규칙 각각): 통과 수, **통과 중 오답**, **정답을 FLAG한 수(오경보)**, 오답 중 FLAG 수, 보류 수.
- 주장 단위: 계산 일치·계산 불일치·보류 수, 보류 사유 RANGE_FILTER_UNSUPPORTED 수.
- 판정이 바뀐 답변 전부.

## 4. 채택 기준 (미리 정함)

다음을 **모두** 만족할 때만 엔진·웹에 v0.7.1을 적용한다.
1. 두 규칙 모두에서 통과 중 오답이 v0.7보다 늘지 않는다.
2. 오경보(정답을 FLAG)가 v0.7보다 늘지 않는다.
3. 범위 때문에 보류된 주장이 줄어든다(효과가 없으면 적용할 이유가 없다).
4. 기존 단위 테스트를 고칠 때는 고친 테스트와 이유를 기록한다.

만족하지 못하면 적용하지 않고 결과만 보고한다. 결과를 본 뒤 고치면 ‘변경 기록’에 남기고 사후 결과로 표시한다.

## 5. 한계

범위 질문이 들어간 저장된 답변은 많지 않을 수 있다(효과 크기가 작게 나올 수 있음). 새 문항은 API 비용 때문에 만들지 않는다.
