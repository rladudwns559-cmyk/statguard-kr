# 규칙 추출기 v0.8 평가 프로토콜 (실행 전 고정)

작성: 2026-11-24. API 호출 없음(저장된 답변만).

## 1. 바꾸는 것 (v0.7 → v0.8)

`statguard_comparison_v0.1`과 오류 역추적에서, 한 문장에 숫자가 여러 개일 때 규칙 추출기 v0.7이 **문장의 마지막 숫자를 문장 전체의 범위(예: 11월)와 연결**해 맞는 답을 ‘계산 불일치’로 판정한 사례가 확인됐다(예: “11월 강수량은 147.0mm이고 총 합계는 888.9mm입니다”).

1. **절 나누기:** “~이고 / ~이며 / ~였고 / ~이었고 / ~였으며 / ~이었으며”로 이어진 문장에서 앞뒤 절 모두에 숫자가 있으면 절마다 따로 주장을 만든다.
2. **전체를 가리키는 절:** 앞 문장(절)의 범위를 이어받는 규칙(v0.5·v0.6)에서, 범위 언급이 없더라도 ‘총·전체·연간’이 있고 앞을 가리키는 말(따라서·이 중 등)로 시작하지 않는 문장(절)은 이어받지 않고 전체 행으로 계산한다.

그 밖의 규칙은 바꾸지 않는다. 이전 실험 결과는 각 실험 폴더의 고정 사본(v0.7 등)으로 재현되며 바뀌지 않는다.

## 2. 데이터

저장된 답변 전부(`statguard_arithmetic_v0.1/run_eval.py`의 `answers()`와 같은 1,492개): 모델 3종의 원래 답변 360개, gpt-6-luna 반복·조건 답변 528개, 교정 실험에서 고쳐 쓴 답변.

## 3. 지표 (v0.7 고정 사본과 v0.8을 같은 답변에 적용)

- 답변 단위(사전 등록 규칙과 최종값 규칙 각각): 통과 수, **통과 중 오답 수**, **정답을 FLAG한 수(오경보)**, 오답 중 FLAG 수.
- 주장 단위: 계산 일치·계산 불일치·보류 수.
- 판정이 바뀐 답변 목록(전부 보고).

## 4. 채택 기준 (미리 정함)

다음을 **모두** 만족할 때만 웹(현재 엔진)에 v0.8을 적용한다.
1. 두 규칙 모두에서 통과 중 오답이 v0.7보다 늘지 않는다.
2. 오경보(정답을 FLAG)가 v0.7보다 늘지 않는다.
3. 기존 단위 테스트를 고칠 때는 고친 각 테스트와 이유를 기록한다.

만족하지 못하면 v0.8을 적용하지 않고 결과만 보고한다. 결과를 본 뒤 규칙을 다시 고치면 그 내용을 ‘변경 기록’에 남기고, 고친 판의 결과는 사후 결과로 따로 표시한다.

## 5. 한계

같은 답변들로 문제를 발견하고 같은 답변들로 평가하므로(새 답변을 받으려면 API 비용이 든다) 개선 폭은 낙관적으로 추정될 수 있다. 처음 적용하는 답변(G2)을 따로 보고한다.

- 2026-11-24, 수정판 결과와 결정: 수정판(사후)은 최종값 규칙 통과 중 오답 1→0, 오경보 66→58, 오답 중 FLAG 183→190이지만 사전 등록 규칙 통과 중 오답은 여전히 13→35로 늘어 **채택 기준을 충족하지 못했다.** 사이트는 답변 단위 ‘통과’를 표시하지 않지만, 기준은 결과를 보기 전에 정한 것이므로 결과를 본 뒤 바꾸지 않는다. **v0.8은 엔진·웹에 적용하지 않고** 이 폴더(`claims_v0_8.py`)에 연구 결과로 보관한다. 더 고치는 것도 멈춘다(같은 답변으로 계속 고치면 그 답변에만 맞춘 규칙이 됨). 남은 새 오경보는 주어 없는 뒤 절을 나눈 경우, 같은 문장 앞 절의 대상(도시 등)을 뒤 절이 잃는 경우, ‘5억 7,276만’ 같은 억·만 이어 쓰기 읽기였다. 다음 판은 답변 단위 판정을 최종값 규칙으로 정하고, 새 답변(새 문항·모델)으로 평가해야 한다.
