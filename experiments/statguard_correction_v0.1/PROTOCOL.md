# StatGuard-KR 자동 교정 실험 프로토콜 v0.1 (실행 전 고정)

작성: 2026-11-24. 이 문서는 교정 요청(LLM 호출)을 하기 전에 작성했으며, 결과를 본 뒤 조건·피드백 문구·지표를 바꾸지 않는다. 바꿔야 하면 아래 ‘변경 기록’에 이유와 함께 남긴다.

## 1. 질문

StatGuard의 검증 결과(재계산 값·계산식·보류 사유)를 일반 LLM에게 돌려주면 답변이 실제로 더 정확해지는가?
그 효과가 ‘다시 한 번 물어본 효과’가 아니라 ‘검증 근거의 효과’인가?

## 2. 대상

- 기존 벤치마크 v0.1(본 36 + 별도 18), v0.2(본 30 + 별도 14), v0.3(본 22) — 총 120문항.
- 각 문항의 **조건 A(일반 LLM, CSV만) 1회차 답변**을 그대로 출발점으로 쓴다(이미 저장된 답변, 새로 생성하지 않음).
- 정답 여부는 각 벤치마크의 `evaluate.py`에 있는 채점 함수(`final_value`, `is_correct`)와 `expected*.json`으로만 판단한다. **기대값은 채점에만 쓰고 모델에게 주는 피드백에는 절대 넣지 않는다.**

## 3. 검증기

- 현재 웹과 같은 규칙 기반 추출기 v0.7(`src/when2warn/statguard/claims.py`). 실행 전 사본을 `frozen/claims_v0_7.py`에 두고 SHA-256을 `frozen/claims_v0_7.sha256`에 기록한다.
- 답변 단위 판정은 기존과 같다: 계산 불일치가 하나라도 있으면 FLAG, 불일치 없이 계산 일치가 있으면 PASS, 그 외 HOLD.

## 4. 교정 대상 선정 (두 조건 공통)

- PASS → 고치지 않는다.
- 답변의 최종값이 ‘판단불가’ → 고치지 않는다(모델의 보류를 존중).
- 그 외(FLAG, 또는 최종값이 있거나 형식 오류인 HOLD) → 교정 대상.
- 두 비교 조건은 **같은 문항 집합**에 적용한다.

## 5. 비교 조건

모델 `gpt-6-luna`, 지시문은 조건 A와 같음, `max_output_tokens` 2500, store=false, 재시도 없음. 대화는 [원래 질문+CSV] → [모델의 이전 답변] → [아래 피드백] 순서로 보낸다.

| 조건 | 피드백 |
|---|---|
| R 단순 재확인(대조군) | “방금 답변을 CSV로 다시 확인한 뒤, 같은 형식으로 답변을 다시 작성하세요. 마지막 줄의 ‘최종값’ 형식을 지키세요.” |
| S StatGuard 근거 피드백(제안) | FLAG: 불일치 주장마다 “문장 / 답변의 수치 / CSV 재계산 값 / 계산식 / 사용한 행 수”를 적고, 일치한 주장은 “확인됨”으로 적는다. HOLD: 보류 사유(사람이 읽는 한국어 설명)를 적고 “어떤 열·기간·계산인지 문장에 드러나게, 숫자를 다시 확인해” 다시 쓰라고 요청한다. 마지막에 R과 같은 형식 지시를 붙인다. |

- 라운드: 최대 2회. 2라운드는 1라운드 결과에 같은 규칙(4장)을 다시 적용한다. 주 결과는 **1라운드**, 2라운드는 보조로 보고한다.
- 대조군 R도 같은 라운드 규칙을 따른다(2라운드 대상은 R 자신의 1라운드 결과를 StatGuard로 판정해 고른다).

## 6. 지표

1. 정답률: A 원래 → R 후 → S 후(1·2라운드), 참고로 기존 C(계산 도구) 정답률과 비교.
2. 전이: 오답→정답(고침), 정답→오답(망침) 건수.
3. 교정 후 StatGuard 판정(FLAG·PASS·HOLD)과 통과 답변의 오답 수.
4. 비용: 호출 수, 토큰, 사전 고정 단가(입력 $0.10/1M, 출력 $0.50/1M) 기준 추정. 실제 청구액은 OpenAI 화면 기준.

## 7. 예산과 중단 기준

- 호출 상한 400회. 먼저 3문항으로 시험 실행 후 형식을 확인하고 전체를 실행한다.
- 응답은 `results/cache/`에 저장해 같은 요청은 다시 호출하지 않는다. 키는 기록하지 않는다.

## 8. 해석 한계(사전 명시)

- S의 피드백은 재계산 값을 포함하므로, 불일치로 잡힌 문항은 고쳐지는 것이 자연스럽다. 이 실험의 관심은 (a) 그 효과의 크기, (b) 보류 문항에서도 효과가 있는지, (c) 정답을 망치는지, (d) 단순 재확인 대비 차이다.
- 120문항·모델 1종·1회 실행의 소규모 실험이며 통계적 유의성은 주장하지 않는다.

## 변경 기록

- 2026-11-24, 본 실행 후 (실험 결과에는 영향 없음): 웹의 ‘근거 보내고 AI에게 고치게 하기’ 기능에서만 피드백 마지막에 “수치는 한 문장에 하나씩 쓰세요.”를 추가했다. 실제 화면 점검에서 모델이 고친 수치 4개를 모두 맞게 썼지만 “~이고, ~이며”로 한 문장에 묶어 규칙 추출기가 전부 보류한 사례가 있었기 때문이다. 이 실험(R·S 조건)은 위 5장의 원래 문구로 수행했다.
- 2026-11-24, 재현성 보완(결과 영향 없음): 이 실험은 보류 사유 문구를 웹의 `answerClient.ts`에서 그때그때 읽었다. 웹에서 기간 범위를 지원하며(v0.7.1) RANGE_FILTER_UNSUPPORTED 문구를 바꾸자, 그 사유가 들어간 피드백 문구가 달라져 저장된 응답을 찾지 못하는 문제가 생겼다. 실행 당시 문구를 `frozen/reasons_ko.json`에 고정하고 실험은 그 사본만 읽도록 했다. 다시 만든 `results/summary.json`이 이전과 바이트 단위로 같음을 확인했다.
