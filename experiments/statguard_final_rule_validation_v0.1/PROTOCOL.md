# ‘최종값 규칙’ 별도 데이터 검증 프로토콜 v0.1 (실행 전 고정)

작성: 2026-11-24. API 호출 없음(저장된 답변만 사용).

## 1. 배경

`statguard_comparison_v0.1`에서, 사전 등록한 답변 판정 규칙(불일치가 있으면 FLAG, 불일치 없이 ‘계산 일치’가 하나라도 있으면 PASS, 그 외 HOLD)이 긴 답변의 ‘중간 수치만 일치·최종값은 보류’인 오답을 통과시켰다. 결과를 본 뒤 **최종값 규칙**(불일치가 있으면 FLAG, 답변의 ‘최종값’이 어떤 ‘계산 일치’ 주장의 재계산 값과 최종값 자신의 자릿수 허용 오차 안에서 같을 때만 PASS, 그 외 HOLD)을 만들었다. 사후에 만든 규칙이므로 규칙을 만들 때 보지 않은 답변으로 다시 확인한다.

## 2. 데이터 (규칙을 만들 때 보지 않은 답변)

기존 벤치마크 v0.1·v0.2·v0.3 본 세트(36+30+22=88문항)의 gpt-6-luna 답변 중 비교 실험에 쓰지 않은 것:
조건 A 반복 2·3회차(`answers_A_r2`, `answers_A_r3`), 조건 B(`answers_B`), 조건 C 1·2·3회차(`answers_C`, `_r2`, `_r3`) — 6세트 × 88 = 528개.
(조건 A 1회차와 별도 검증 세트 A는 비교 실험에서 이미 봤으므로 제외한다.)

한계: 문항과 모델은 규칙을 만들 때와 같다(같은 질문의 다른 실행·조건). 새 문항·새 모델 검증은 아니다.

## 3. 방법

각 답변에 규칙 추출기 v0.7(고정 사본 `../statguard_correction_v0.1/frozen/claims_v0_7.py`)을 적용해 두 규칙의 판정을 구하고, 각 벤치마크의 `evaluate.py`·`expected.json`으로 채점한다. 최종값 규칙의 코드는 `../statguard_comparison_v0.1/analyze_final_rule.py`의 `final_rule`을 그대로 쓴다(수정하지 않음).

## 4. 지표

규칙별: 통과(PASS) 수, **통과 중 오답 수(주 지표)**와 Clopper–Pearson 95% 상한, 오답 중 FLAG 수, 정답을 FLAG한 수, 통과 비율. 세트별·전체.

## 5. 판정 기준 (미리 정함)

최종값 규칙의 통과 중 오답이 0건이면 ‘별도 데이터에서도 유지됨’, 1건 이상이면 사례를 그대로 보고하고 규칙을 고치지 않는다(고치면 다시 사후 규칙이 되므로).
